## Exciting Summer

This past week has been one of the most exciting of the summer! 

- We finished on Monday. Over the weekend, it consisted primarily of squashing any remaining bugs on my end, while Ellie finished up testing and last-minute poster/paper changes. Haha, I've learned that debugging distributed applications is a pain in the lower middle back.

- Since Monday until today, I have been primarily working on trying to improve the implementation.

- So far, I have improved startup time by making various smaller changes like initialization routines, etc. We haven't rerun all the experiments again, so I'm not sure how fast overall it is, but I did run it on adder size 30 and got a Compute Time of 0.495, whereas on Sunday for the same experiment, we got a Compute Time of 15.258.

- The second change/improvement I made was to the memory footprint. As with the startup time improvement, I'm not actually sure how much "better" it is now, but in theory, it should be allocating significantly less memory. This is because in the old implementation, the host node would have to pad subcircuit probability tensors to be the same size, since PyTorch doesn't like jagged arrays. This meant for certain problem instances we could be allocating Gigabytes of space when we only needed Megabytes. I fixed this by just flattening all the probability tensors involved in a single Kronecker product into one larger 1D tensor with no padding, and then passing that to the worker nodes along with some metadata on how to unflatten it.

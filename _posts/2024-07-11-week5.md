## Resolving the Segfault Issue

At the beginning of this week, we encountered a significant challenge with our CutQC codebase. A persistent segfault was occurring, which we traced back to the TensorFlow Data Parallelism API. The issue arose when the API was passed a tuple under certain circumstances.

To address this, I rewrote the compute function responsible for reconstructing the probability vector. The new implementation successfully eliminates the segfault.

## Transitioning to PyTorch

Following our meeting with Dr. Martonosi this week, we are considering potentially transitioning to PyTorch instead of using TensorFlow. There are a couple of motivating reasons for this, but I think one of the bigger ones is that we could use the [PyTorch Distributed API](https://pytorch.org/docs/stable/distributed.html) to implement the reconstruction component as a distributed application. I've dedicated time to exploring this option. Specifically, I've been studying PyTorch documentation.

## Design Thoughts

Our current focus is on optimizing the reconstruction process. The plan is to utilize each GPU node to compute a batch of Kronecker products, followed by sum-reducing the results to the master node. I'm aiming to complete this implementation by next week.
